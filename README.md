# Music Analysis Studio

A native iPad and Mac workspace for inspecting the structure of local audio. Apple’s Music Understanding framework analyzes the selected file on device; the app presents timing, loudness, key, pace, and instrument activity alongside playback.

## Workflow

Import an unprotected audio file, wait for analysis, and inspect the report. Use the playback slider or select a section to seek. Reports and audio copies remain available after relaunch. Export a JSON report for editing tools or further analysis.

- Rhythm: beat positions and estimated overall tempo, with missing-tempo handling.
- Structure: ordered section time ranges. The app does not invent verse/chorus labels.
- Key: detected tonal regions and major/minor mode.
- Loudness: integrated level and momentary measurements over time.
- Pace and instrument activity: native Swift Charts timelines for the returned measurements.
- Local playback, cancellation, saved reports, and explicit report export.

## Run

Open `Music Analysis Studio.xcodeproj` with Xcode 27. Targets: iPadOS 27 and macOS 27. Bundle ID: `com.dd.musicanalysisstudio`. Mac builds use ad-hoc signing; select your own team for a physical iPad.

`Tests/Fixtures/StudioPulse.wav` is an original 16-second synthesized pulse/chord fixture, generated by `Scripts/GenerateFixture.py`. It contains no recorded music or licensed samples. Use it to try the import workflow. Analysis can take a few minutes on a cold system; playback never starts automatically.

## Engineering

`MusicLibrary` bounds imports to 100 MB and durations to 2 seconds–20 minutes. It copies the selected file, validates AVFoundation metadata, runs a cancellable `MusicUnderstandingSession`, validates finite timing/metric values, and atomically saves the report. Cancelled or failed imports remove only their newly staged audio copy. Original files remain untouched.

`MusicModel` owns main-actor presentation and playback. Generation identifiers discard stale analysis results. Native sidebar selection drives report navigation. Files and analysis are local; no account, network entitlement, telemetry, or cloud sync is included.

## Verification

```sh
swift test
swift test -c release
bash Scripts/test-ui.sh
```

Core tests run all six analysis types on the original audio fixture, reopen the saved report, compare original bytes, validate time/pitch formatting, and verify failed-import cleanup. The native workflow imports through the standard panel, waits for analysis, and reopens the report after relaunch. GitHub Actions retains screenshots in the result bundle.

## Interpretation

Results are estimates, not musicological or mastering certification. Sparse or short audio may have no reliable tempo, key, or structure. Charts preserve the framework's measurements and show missing analysis explicitly. Report export includes the selected file's display name and derived metrics, but no source audio or original filesystem path.

There is no streaming catalog integration, DRM bypass, stem separation, audio editing, or background playback mode. Use audio you are permitted to analyze.
